# Mission Reflection

Automation is important when managing hundreds of cloud servers because it saves time and reduces repeated manual work. Instead of running the same commands on every server, administrators can use scripts to perform tasks faster and more consistently. In this activity, I learned how a backup script can help protect important files.

However, automation can also be dangerous when a script contains a mistake. For example, a destructive command scheduled on 1,000 servers could delete important files across many systems. This is why scripts should be reviewed and tested carefully before being used on a large number of servers.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. A Bash script contains commands that perform tasks step by step, while Docker Compose YAML describes how containers and their services should be configured. Both are useful, but they have different purposes.

Looking back at my GitHub repository from Laboratory 1 to Laboratory 9, I can see how my understanding of Cloud Computing has improved. I learned about cloud infrastructure, containers, data management, deployment, operations, security, and automation. I now understand better how these different areas work together to keep cloud systems organized and running properly.

The role I enjoyed most was the Cloud Automation Engineer because I liked learning how to make repeated tasks run automatically. Creating the backup script and setting up the Cron schedule showed me how a simple script can make work easier and reduce manual effort. At the same time, this mission taught me that automation requires careful testing and monitoring. Overall, I learned that automation is helpful, but it must be used responsibly to avoid mistakes that could affect important data and systems.
