# Mission Reflection

This laboratory activity helped me understand the basic parts of cloud infrastructure. Before doing this activity, I mostly knew cloud computing as a way of using services online. After checking the Linux server in KillerCoda, I understood better that cloud services still need resources like CPU, memory, storage, networking, and an operating system.

For me, the most important cloud infrastructure component is compute. Applications need processing power to run, and without enough compute resources, the system may become slow or may not be able to handle the work. Storage and networking are also important, but compute is what allows applications and services to actually process tasks.

Linux supports cloud computing by providing an operating system that can run on cloud servers. It allows users and administrators to manage files, check system resources, run programs, and use commands through the terminal. Using KillerCoda gave me a chance to practice these things on a cloud-based Linux environment.

Technical documentation is important before deploying infrastructure because it gives engineers a clear plan. It also helps them understand what resources are needed and how the different parts of the system will work together. Good documentation can also make it easier to find problems and maintain the system later.

During this activity, I learned how to check CPU information, memory, storage, networking information, and the operating system using Linux commands. I also learned how to compare similar services from AWS, Azure, and Google Cloud. Creating the cloud architecture diagram helped me understand how the different components connect.

My GitHub portfolio also improved because I added another complete laboratory activity. It now contains more technical documentation, screenshots, a cloud provider comparison, and a cloud architecture diagram. This makes the portfolio more organized and shows the progress I am making in learning cloud computing.
